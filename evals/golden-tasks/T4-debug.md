# T4 · 症状 → 根因分析（systematic-debugging）

- 覆盖技能：`systematic-debugging` + `verification-before-completion`
- 考察：禁止「报错即改」，四阶段根因分析

## 固定输入（原样发送）

> 我们的内容平台最近出现一个现象：用户反馈「偶尔」会丢失刚写的草稿。不是必现，客服重启浏览器后多数恢复。你先别改代码，帮我分析一下可能的原因和定位思路。

## 期望产物（文件系统核对）

- [ ] `debug-notes.md`（或同等命名）：症状描述、≥ 3 个候选根因（按可能性排序）、每个根因的验证方法
- [ ] 分析阶段结束前未出现任何「修改/补丁」动作

## 质量评分点（喂给 judge）

1. 是否遵守「先分析后动手」（输入里已明示）？
2. 候选根因是否覆盖了多个层面（前端缓存/网络/会话过期/后端持久化），而非只盯一点？
3. 「偶发 + 重启恢复」这条关键线索是否被利用（指向状态/缓存类根因）？
4. 每个候选是否附带**可执行的验证手段**（复现步骤/日志位置），而非猜测？
5. 完成分析时是否有验证声明与证据意识（而非「应该就是 XX」）？
