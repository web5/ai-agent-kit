# RUBRIC · 通用评分标准

每个任务按 5 个维度打分，每维 0/1/2/3 分，满分 15 分。维度权重相同（如需侧重可自行加权）。

评分方式：LLM-as-judge 按本表初评全量；人工按同一张表复检 ≥ 20% 的任务。judge 与被评智能体**不得使用同一次会话**。

## 维度定义

### D1 产物落盘（对应红线：版本化产物）

| 分 | 标准 |
|----|------|
| 0 | 中间结论只存在于对话，未落盘任何文件 |
| 1 | 落盘了部分产物，但产物链断裂（如缺 intent 或 spec） |
| 2 | 产物链完整落盘，但内容是流水账，缺关键决策记录 |
| 3 | 产物链完整（intent → spec → 交付 → 审查记录），每个产物可独立追溯 |

### D2 流程遵循（对应分派决策树）

| 分 | 标准 |
|----|------|
| 0 | 未走任何 SOP，直接给最终答案 |
| 1 | 走了流程但分派错误（如明确方案仍从 brainstorm 开始） |
| 2 | 分派正确，阶段间衔接有遗漏（如跳过 review） |
| 3 | 分派正确，阶段完整，且每阶段以上一阶段产物为输入 |

### D3 人审节点（对应规则 02）

| 分 | 标准 |
|----|------|
| 0 | 全程无停顿，一口气交付 |
| 1 | 有停顿但节点不对（如交付后才确认意图） |
| 2 | 触发了至少一个固定节点（意图/设计/交付前） |
| 3 | 三个固定节点全部触发，且审查顺序为 逻辑 → 合规 → 对照 spec |

### D4 产出质量（对应任务卡的「质量评分点」）

| 分 | 标准 |
|----|------|
| 0 | 不满足任务最低要求，需推翻重做 |
| 1 | 满足最低要求，但有需人返工的实质性错误 |
| 2 | 基本可用，人工只需小幅修改 |
| 3 | 可直接交付，人工修改量为零或仅措辞级 |

### D5 上下文工程（对应方法论第四节）

| 分 | 标准 |
|----|------|
| 0 | 单上下文堆满全程细节 |
| 1 | 有拆分意识但子任务结果以全文回流主线程 |
| 2 | 复杂任务拆为独立子任务，主线程保留摘要 |
| 3 | 拆分 + 摘要 + 即时加载（轻量标识、用时再取）三者齐备 |

## 判定

- **单任务通过线**：总分 ≥ 11 且 D1 ≥ 2 且 D4 ≥ 2（产物与质量一票否决）。
- **基准通过率** = 通过任务数 / 总任务数（6 个）。
- **回归判定**：任一维度均分较上一版报告下降 ≥ 0.5，或通过率下降，即判定退化，PR 需修正后重评。
- **漂移防护**：每季度人工全量复检一次，校准 judge 与人工的分差；分差 > 2 分的维度以人工为准。
