# T3 · 写作执行 → 交付（execute + review）

- 覆盖技能：`rd-execute` + `rd-review`
- 考察：依据 spec 落地、迭代-校验、交付前审查

## 固定输入（原样发送）

> 按照下面的 spec 写一份面向全员的工具迁移公告（~300 字），要求：迁移原因、影响范围、时间表、求助渠道四节齐全，语气平和不制造焦虑。
>
> SPEC：下周一起，团队文档从旧平台迁移到新平台；旧平台只读保留一个月；每人需自行迁移个人空间；疑难在互助群提问。

## 期望产物（文件系统核对）

- [ ] `announcement.md`：成稿，四节齐全
- [ ] `review-record.md`（或成稿内嵌审查记录）：自检结果（对照 spec 逐项）

## 质量评分点（喂给 judge）

1. 四节是否齐全且信息与 spec 一致（无编造细节）？
2. 语气是否达成「平和不制造焦虑」（无「必须」「限期」式压迫用语堆砌）？
3. 自检记录是否真的逐条对照了 spec，而非空泛的「已检查」？
4. 字数是否在合理区间（±30%）？
