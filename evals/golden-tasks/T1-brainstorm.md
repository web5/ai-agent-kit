# T1 · 模糊需求 → 方案探索（brainstorm）

- 覆盖技能：`rd-brainstorm`（经 `rd-digital-agent` 分派）
- 考察：模糊意图的结构化、方案多样性、人审节点

## 固定输入（原样发送）

> 我们团队最近协作效率很低，事情经常要返工。帮我改善一下这个情况。

## 期望产物（文件系统核对）

- [ ] `intent.md`：包含目标、受众、范围边界、成功标准四要素
- [ ] `options.md`（或同等命名）：≥ 2 个实质不同的方案，各有优劣与推荐结论
- [ ] 方案确认前有明确停顿等待人选择（对话或产物中可辨识）

## 质量评分点（喂给 judge）

1. 意图是否先于方案被澄清（而非直接抛方案）？
2. 方案之间是否真正互斥（而非同一方案的措辞变体）？
3. 是否主动界定了范围边界（不试图一次解决所有问题）？
4. 是否给出了可比较的取舍维度（成本/风险/见效周期）？
