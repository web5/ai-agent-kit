# L2 路由用例集（routing）

测什么：给典型用户请求，Hub（`rd-digital-agent`）是否分派到正确 skill。自动对比分派决策，二元判定（对/错）。

用法：每条用例在干净上下文中原样发送给加载了本 kit 的智能体，记录其首个分派决策（或实际走的工作流），与「期望分派」比对。改动分派决策树（SKILL.md）或新增 skill 后必须重跑全量。

> 用例输入一经固定不得修改；新增用例只追加不改动。

## 用例

| # | 输入（原样发送） | 期望分派 |
|---|------|---------|
| R1 | 「我们团队协作效率低，帮我改善一下」 | `rd-brainstorm` |
| R2 | 「这块怎么做才好？给我几个思路」 | `rd-brainstorm` |

| R4 | 「把这个已确定的需求细化成 TODO」 | `rd-plan` |
| R5 | 「按这份 spec 把公告写出来」 | `rd-execute` |
| R6 | 「这个小错别字顺手改一下」 | `rd-execute`（直连，不走完整流水线） |
| R7 | 「执行完了，自检一下产物质量」 | `rd-review` |
| R8 | 「帮我把这份交付物过一遍质量审查」 | `rd-review` |
| R9 | 「这个方案的架构选型帮我把把关」 | `tech-review` |
| R10 | 「这段设计有没有安全隐患/信息结构问题」 | `tech-review` |

| R23 | 开发产物就绪后：「帮我独立测一下是不是真的满足需求」 | `test-verification`（独立第三方盲测，先于人审） |
| R24 | 「这段实现有点啰嗦，帮我精简一下」（纯代码产出质量） | 产出纪律（`AGENT.md` §产出纪律：简洁至上；不触发流水线） |
| R25 | 「改动比较多，想隔离着改，别影响当前工作区」 | `rd-execute` §隔离工作区（worktree 约定） |
| R26 | 「这几处互不相干，能不能同时推进」 | `rd-digital-agent` §多 Agent 协作团队模式（分派前提：无共享文件、无顺序依赖） |
| R27 | 「提交前帮我请一轮代码评审」 | `rd-review` §请审 / 接审纪律（须附变更范围 + 验证证据 + 已知取舍） |
| R28 | 「用 brainstorming 帮我发散一下这个需求」 | `rd-brainstorm`（编排权唯一：同域同名以 `rd-*` 为准，非编排类技能照常启用） |

## 判定与指标

- **路由准确率** = 正确分派数 / 28。
- R18 为过程性用例：检查任意任务的完成声明是否先过了验证门。
- R1/R3/R6/R11/R13/R15/R21/R22/R23/R24/R28 十一条为核心用例（覆盖 Hub 决策树主干分支、三类资产路由与编排权唯一性），核心用例出错权重加倍。
- R24~R28 为三类资产咬合用例：R24 测产出纪律是否生效而非走流水线；R25~R27 测工程纪律是否命中对应实体（`rd-execute` / `rd-digital-agent` / `rd-review`）；R28 测编排权唯一（同域同名以 `rd-*` 为准）。
- 准确率 < 90% 视为路由层不达标（成熟度 M2 门槛）。
