# L2 路由用例集（routing）

测什么：给典型用户请求，Hub（`rd-digital-agent`）是否分派到正确 skill。自动对比分派决策，二元判定（对/错）。

用法：每条用例在干净上下文中原样发送给加载了本 kit 的智能体，记录其首个分派决策（或实际走的工作流），与「期望分派」比对。改动分派决策树（SKILL.md）或新增 skill 后必须重跑全量。

> 用例输入一经固定不得修改；新增用例只追加不改动。

## 用例

| # | 输入（原样发送） | 期望分派 |
|---|------|---------|
| R1 | 「我们团队协作效率低，帮我改善一下」 | `rd-brainstorm` |
| R2 | 「这块怎么做才好？给我几个思路」 | `rd-brainstorm` |
| R3 | 「方案定了：周报改模板制，帮我拆成任务列表」 | `rd-plan` |
| R4 | 「把这个已确定的需求细化成 TODO」 | `rd-plan` |
| R5 | 「按这份 spec 把公告写出来」 | `rd-execute` |
| R6 | 「这个小错别字顺手改一下」 | `rd-execute`（直连，不走完整流水线） |
| R7 | 「执行完了，自检一下产物质量」 | `rd-review` |
| R8 | 「帮我把这份交付物过一遍质量审查」 | `rd-review` |
| R9 | 「这个方案的架构选型帮我把把关」 | `tech-review` |
| R10 | 「这段设计有没有安全隐患/信息结构问题」 | `tech-review` |
| R11 | 「跑测试报错了：……（错误信息）」 | `systematic-debugging` |
| R12 | 「用户反馈功能偶尔行为异常，查一下」 | `systematic-debugging` |
| R13 | 「这块代码重复太多，清理一下」 | `incremental-refactoring` |
| R14 | 「在不改行为的前提下重构这个模块」 | `incremental-refactoring` |
| R15 | 「这个功能是在哪实现的？」 | `code-explore`（只读） |
| R16 | 「帮我理一下这个项目的整体结构」 | `code-explore`（只读） |
| R17 | 交付收尾阶段：「都做完了吗？」 | `verification-before-completion` |
| R18 | 任意任务完成声明前 | 必须经过 `verification-before-completion`（质量门） |
| R19 | 「记住：我们团队文档统一用简体中文」 | `user-memory` |
| R20 | 「上次让你记住的偏好是什么？」 | `user-memory` |

## 判定与指标

- **路由准确率** = 正确分派数 / 20。
- R18 为过程性用例：检查任意任务的完成声明是否先过了验证门。
- R1/R3/R6/R11/R13/R15 六条为核心用例（覆盖 Hub 决策树的主干分支），核心用例出错权重加倍。
- 准确率 < 90% 视为路由层不达标（成熟度 L2 门槛）。
