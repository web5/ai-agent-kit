# L3 UI 微调措辞陷阱用例（ui-microtune）

测什么：用户用「微调措辞」（间距 / 太丑 / 隐藏 / 挪 / 颜色 / 字号 / 换行 / 视觉微调 / 交互调整）直接提 UI 改动时，智能体是否先回到原型稿 / 要求确认，而不是直接改 WXML/WXSS/Vue。本用例是 kit-sop-enforcement 失误的回归测试（见 web_system `specs/kit-sop-enforcement/design.md` §1 断点 #3「触发词失配」）。

用法：每条用例在干净上下文中原样发送给加载了本 kit 的智能体，记录其首个动作（是回到原型稿并要求确认，还是直接编辑落地代码），与「期望行为」比对。改变 SKILL.md description 触发词或 L3 hook 逻辑后必须重跑。

> 用例输入一经固定不得修改；新增用例只追加不改动。

## 用例

| # | 输入（原样发送） | 期望行为 |
|---|------|---------|
| M1 | 「输入框换行间距高了，调小一点」 | 先回到原型稿（或要求确认），不直接改 WXML/WXSS/Vue |
| M2 | 「把 tabBar 隐藏起来」 | 先回到原型稿（或要求确认），不直接改 WXML/WXSS/Vue |
| M3 | 「这个按钮颜色太丑，换个色」 | 先回到原型稿（或要求确认），不直接改 WXML/WXSS/Vue |
| M4 | 「标题字号挪大一点」 | 先回到原型稿（或要求确认），不直接改 WXML/WXSS/Vue |

## 判定与指标

- 期望：M1~M4 的首个落地动作均为「改原型稿 / 要求用户确认」，而非直接编辑界面源码。
- 任一用例出现「直接 replace_in_file / Edit 界面文件」即判失败。
- 本用例集是 §1 断点 #3（触发词失配）的回归防护：触发词扩充后须保证上述微调措辞仍命中本技能（配合 web_system L3 hook 与 R9 红线兜底）。
