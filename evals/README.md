# evals · 回归评测体系

评估本 kit 的进化程度。核心原则：**用 kit 自己的方法论评估它自己**——更新是 intent，评测报告是回归证据，退化即阻断。

本目录是 `references/eval-framework.md`（评测体系定稿）的落地实现，五层结构见下。

## 评什么（五层，由便宜到贵）

| 层 | 对象 | 手段 | 成本 |
|----|------|------|------|
| **L1 结构完整性** | 文件齐全、无孤儿 skill、frontmatter、占位残留、路由指向存在 | 静态脚本 + CI（`eval-gate.yml`，用例化见 `cases/structure.md`） | 近零 |
| **L2 路由准确率** | Hub 是否分派到正确 skill | `cases/routing.md`（20 条，二元判定） | 低 |
| **L3 行为遵循度** | 红线是否被静默违反 | `cases/behavior.md`（6 条陷阱） + rubric | 中 |
| **L4 端到端质量** | 完整产物链的产出质量与成本 | `golden-tasks/`（T1~T6 + RUBRIC） + 产物清单核对 | 高 |
| **L5 实战验证** | 真实世界是否变好 | 真实项目人审打回率、红线拦截次数、复盘回灌记录 | 极高 |

指南的价值不在于写得好，而在于**让智能体干活更符合预期**，所以动态层（L2~L5）是核心。

## 怎么跑（每次 kit 变更后）

> **首份基线必须按 `run-baseline.md` 执行**（干净上下文 + judge 隔离，防止自评污染；同 agent 同会话跑出的分数不可作为基线）。日常回归评测按下列六步。

1. **锁定基准**：记录本次 kit 的 commit hash 与变更摘要（写入报告头部）。
2. **重放任务**：对 `golden-tasks/` 全部 6 个任务卡，用**同一模型、同一温度、同一任务输入**各跑一遍（建议每个任务跑 2~3 次取均值，抑制随机性）。
3. **核对产物**：对照任务卡的「期望产物清单」，检查文件系统里是否真的落盘（红线三：版本化产物）。
4. **评分**：按 `RUBRIC.md` 逐维度打分。LLM-as-judge 初评全量，人工复检不低于 20%。
5. **落盘报告**：复制 `reports/TEMPLATE.md` 为 `reports/<commit短hash>-<日期>.md`，填写分数表与对比结论。
6. **门禁**：涉及 `skills/` `rules/` `AGENT.md` `references/` 的 PR，必须同时包含 `evals/reports/` 的新增报告，否则 CI 拦截（`.github/workflows/eval-gate.yml`）。

7. （可选）**脚本化执行**：被测 Agent 可无头调用时，用 `scripts/run-eval.sh` 编排 + `scripts/check-artifacts.sh` 核对产物 + `scripts/gen-report.sh` 出报告骨架，`AGENT_CMD` 规范与全流程见 `run-baseline.md`「脚本化执行」章节。

L2/L3 用例（`cases/routing.md`、`cases/behavior.md`）为轻量级，每次更新单独跑，不与 L4 任务卡混跑。

## 进化程度怎么看

单次分数没有意义，**「随版本单调改善」才是进化**。看 `reports/` 时间序列的趋势线：

- 一次通过率 ↑
- 人工修改量（返工）↓
- 红线违规数 ↓
- 产物落盘率 → 100%

回归判定：任一维度均分较上一版下降 ≥ 0.5，或通过率下降 → 判退化，本次变更不合并。

## L5 实战验证（真实世界是否变好）

L5 不是主动跑的用例，而是**长期积累的真实使用信号**，季度统计一次。它是唯一直接度量「真实世界变好」的层，避免评测在真空中自证。

### 数据来源

| 指标 | 来源 | 采集方式 |
|------|------|---------|
| 人审打回率 | `rd-review` / 真实项目审查记录 | 统计交付物被人工打回的比例 |
| 红线拦截次数 | `rules/general/*` 的机器检查触发记录 | 统计 CI/pre-commit 拦截次数 |
| 复盘回灌记录 | 复盘产物 `retro.md` 及后续 intent 变更 | 核对复盘结论是否形成新一轮 kit 变更 |

### 判据（成熟度 L5 达标）

- 人审打回率**随版本下降**；
- 红线拦截次数**先升后降**（机器拦截生效 → 同类错误减少）；
- 复盘结论**有回灌记录**（复盘 → 新一轮 intent → 再次评测，闭环可追溯）。

## 成熟度分级（L0~L5）

| 级 | 特征 | 判据 |
|----|------|------|
| L0 | 无指南，靠对话临时指挥 | 无 |
| L1 | 有指南层（偏好、禁忌） | `AGENT.md` 存在并被加载 |
| L2 | 有 SOP + 版本化产物链 | skills 就位，任务产物落盘率 ≥ 80% |
| L3 | 红线机器化 | 反复错误有 CI/机器拦截（L1 五检查项全过） |
| L4 | 回归评测闭环 | 每次演进有基准对比，退化可发现并可阻断 |
| L5 | 实战验证 | 真实项目人审打回率下降、复盘回灌有记录 |

本 kit 当前位于 **L3 尾部**：三层结构、机器红线（L1 结构检查）、L2~L4 用例集均已就绪，补齐本 `evals/` 并**跑出首份基线报告**后进入 L4；L5 需在真实项目中积累数据。
