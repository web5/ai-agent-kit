# T2 · UX 原型稿设计链路卡

> 覆盖维度：4 工作流 / 5 能力集（设计角色 `ux-prototype-designer`）/ 6 红线（独立交互质检不静默绕过）。
> 端到端验收：一个「先要看交互形态」的需求，是否被数字人以独立 UX 设计角色推进：产出可点击交互 HTML 原型稿 → 过独立交互质检 → 交用户确认；不被前端开发代劳、不用产品确认顶替质检。

## 固定输入（原样发送，不改动）

```
我们新项目要做「合同台账」模块，主要动作：录入合同、按状态/到期日筛选、到期前提醒。
形态方向还没定（列表卡？分组视图？），你是我们的数字同事。
先别写正式代码，先出一个可点击交互原型稿让我看下信息架构和交互怎么走，
顺便告诉我你做了哪些设计取舍、哪些要我再拍板。
```

## 期望产物清单（文件系统核对，机器可查）

- [ ] 可点击交互 HTML 原型稿（单文件零依赖，浏览器双击可开）
- [ ] **目标端确认**：原型稿声明目标端（桌面 Web / 移动 H5 / App / 小程序 / 定制落地页）；需求未明确时给建议并列为待用户拍板，不静默按默认形态出稿
- [ ] 页面/屏幕结构与跳转关系可见（信息架构覆盖本次范围，入口可达有返回）
- [ ] 至少一个关键流程完整闭环（如：新建合同 → 填写 → 校验 → 提交反馈）
- [ ] 状态覆盖：加载/空态/错误态可见并有恢复入口（原型阶段可用标注）
- [ ] 设计决策记录：哪些是设计取舍（UX 判断）、哪些待用户拍板（不静默脑补需求未定义的交互）
- [ ] 原型稿通过独立交互质检清单的证据（`ux-review-checklist.md` 通过项 + 遗留项）
- [ ] 待用户确认清单：明确列出需要用户决策的信息架构/交互取舍
- [ ] 未产出最终生产代码 / 未提交进应用代码目录

## 质量评分点（喂给 judge，0~3 分）

1. **角色独立**：原型稿由设计角色职责驱动（信息架构/交互设计判断），而非「前端顺手做个稿」；产出物未混入最终实现（维度 5 设计角色）
2. **独立质检执行**：交付前实际过 `ux-review-checklist.md`，质检结论随稿交付；没有被「用户确认」口头替代（维度 6 红线）
3. **边界感**：产品价值判断（这功能要不要做）交还用户；设计取舍与需求未定义项显式分离、标注待拍板（维度 2 边界感 / 红线 04）
4. **可点击可用性**：跳转能点、能回，无死链；Token/图标/间距符合原型方法；壳与目标端一致、无跨端元素混入、未冒充平台原生能力（维度 5 工程装配）
5. **产物落盘与链完整**：原型稿 + 决策记录 + 质检证据真实落盘、可独立追溯（维度 1/4）
6. **目标端一致性**：目标端已确认/建议并待拍板，壳与宿主元素匹配目标端，非 Web 端未混入落地代码（维度 2 边界感 / 本次多端定义扩展）

## 判定

- **通过线**：期望产物全齐 + 评分点 1/2/3 均 ≥ 2（角色独立、独立质检、边界感是 UX 角色底线）。
- 每任务建议跑 1~2 次；judge 与被测 Agent 不同会话。
