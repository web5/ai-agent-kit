# golden-tasks · 数字人端到端基准任务集

> 本目录 = **数字人技术产品型评测**的端到端任务卡（L4 形态），测的是"第 1 号数字人实例（技术型产品经理人格）符不符合它的画像定义、能不能端到端干成一件正经事"。
> 它是**质量评分型**（judge 按评分点打分），不同于 `cases/` 里的二元判定用例（对/错）。
> ⚠️ 与 `evals/golden-tasks/` 不同：那套测的是**方法论本身**（kit 进化回归），本目录并入 `digital-agent-eval/`，两者内容各自实例化、不混用。

## 一句话：为什么叫 "golden"

任务输入**一经冻结不改**（改了 = 换基准，历史报告全部作废）。同一次评测里每张卡用同一道题、同一个期望产物清单、同一套评分点，成绩才能跨版本对比——这就是"金标准"的意义。

三要素缺一不可：

| 要素 | 含义 | 谁判定 |
|------|------|--------|
| **固定输入** | 卡里那一段话，原样发给被测智能体，一个字不改 | — |
| **期望产物清单** | 要求真实落盘到文件系统的产物（如 `intent.md`），存在性可脚本核对 | 机器/脚本 |
| **质量评分点** | 产出"好不好"的 0~3 分维度，喂给 judge | LLM-as-judge / 人工 |

## 任务卡一览

每张卡覆盖画像的若干验收维度（维度编号见 `references/digital-agent-profile.md`），验证数字人在某个**完整工作链路**上的表现：

| ID | 链路 | 端到端验收（一句话） | 底线评分点（通过线卡这几点） |
|----|------|---------------------|------------------------------|
| `T1-tech-pm` | 技术产品经理 | 模糊产品想法 → 需求辨证 → 方案对比（≥2 形态）→ 价值取舍交人拍板 | 价值导向 / 懂技术 / 边界感 均 ≥2 |
| `T2-ux-prototype` | UX 原型设计 | 需求 → 可点击交互 HTML 原型稿 → 独立交互质检 → 交用户确认（不被前端代劳、不用产品确认顶替质检） | 角色独立 / 独立质检 / 边界感 均 ≥2 |
| `T3-systematic-debugging` | 系统化调试 | 报错症状 → 四阶段根因分析 → 受控修复 → 实际验证后才声明完成 | 根因优先 / 验证证据门 均 ≥2 |
| `T4-incremental-refactoring` | 增量重构 | 测试保护下小步重构：只动结构不动行为、每步可验证、不借机改功能 | 行为不变 / 验证证据门 均 ≥2 |
| `T5-explore-and-tech-review` | 探索 + 技术审查 | 只读代码探索定位实现与影响面 → 多维技术审查；不动码、材料不足显式要补不硬评 | 只读纪律 / 材料不足即停 均 ≥2 |
| `T6-verification-gate` | 交付前验证门 | 「帮我看看完成没」→ 必须实测给证据才可上线；需求没定义的行为显式提醒、不发明兜底 | 验证证据门 / 无业务定义不发明兜底 均 ≥2 |

> 演进趋势：T1/T2 先立（tech-pm / ux-prototype 两条链路），T3~T6 于 2026-09 补齐，把调试、重构、探索审查、验证门四条"方法论红线链路"也纳入端到端验收。

## 卡结构（每张卡统一排版）

1. **头部引用块**：覆盖维度 + 端到端验收目标
2. **固定输入**：``` ``` 框住的一段话，评测时原样注入
3. **期望产物清单**：文件系统核对项（checklist 形式，可机器查）
4. **质量评分点**：0~3 分维度，喂给 judge
5. **判定**：通过线（产物全齐 + 指定底线评分点 ≥2）+ 跑次建议（1~2 次，judge 与被测 agent 不同会话）

## 怎么用

1. 被测数字人加载本仓库（AGENT.md + skills + rules + 画像为参考），在**干净工作区**运行。
2. 选一张卡，把「固定输入」原样发给被测数字人，不附加任何提示。
3. 等它收尾后，先机器核对「期望产物清单」是否落盘，再把「质量评分点」连同产物一起交给 **judge（不得与测的是同一会话）** 打分。
4. 结论落盘到 `../reports/<画像commit>-<日期>.md`（用 `../reports/TEMPLATE.md`），首份即基线。

## 雷区（记住了省得翻车）

- 固定输入**冻结**：评测中不解释、不补充、不改题；改卡 = 换基线。
- judge 与数字人**不同会话**，防自评污染。
- 产物没落盘 / 评分点不过线 = 不通过，不因"答得差不多"放水。
- 本目录的画像/人格一旦变更（换人格、换定义版本），须重跑全部历史任务建立新基线。
