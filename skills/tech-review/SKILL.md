# 方案审查 (Tech Review)

## 何时触发

当用户给出或 AI 提出涉及以下任一方面的方案时，自动启动审查：
- 新建 / 拆分资料或模块
- 信息结构或存储方案变更
- 对外交付物 / 契约设计
- 内容架构或模板结构变更
- 发布 / 运行方案
- 安全相关（权限、数据保护）
- 第三方工具选型
- 工具链 / 技术选型

不触发：小修、文案修改、单文件微调。

---

## 审查维度

### 1. 结构与边界
- 单元职责是否单一？
- 是否需要新建，还是可复用现有？
- 单元间是否通过明确契约通信？

### 2. 安全设计
- 是否需要权限模型？是否最小权限？
- 敏感数据是否加密 / 脱敏？
- 是否有操作记录？

### 3. 信息设计
- 是否满足结构规范与检索 / 复用模式？
- 是否有清晰的分类 / 标签 / 索引？
- 是否需要版本 / 草稿状态标记？

### 4. 规模与复用
- 是否有重复内容可模板化复用？
- 长任务是否拆分为可独立交付的单元？
- 是否支持多人 / 多渠道复用？

### 5. 可维护性
- 是否有质量校验 / 可验证手段？
- 关键修改是否有记录 / 版本？
- 约定是否可配置 / 集中管理？

详细标准见 `references/design-principles.md`；逐项检查见 `references/review-checklist.md`。

---

## 输出格式

审查完成后，按以下格式输出：

```markdown
## 方案审查

### 方案概述
> 一句话描述

### ⚠️ 风险项（必须解决）
- [ ] 风险1：描述 + 建议

### 💡 优化建议（建议采纳）
- [ ] 建议1：描述

### ✅ 合理项（无需改动）
- 项1：理由

### 综合评分
结构: ⭐⭐⭐⭐ / 安全: ⭐⭐⭐ / 信息: ⭐⭐⭐⭐ / 规模: ⭐⭐⭐

### 结论
✅ 通过（建议优化后执行）/ ⚠️ 有条件通过 / ❌ 需重新设计
```
