# 方案审查 (Tech Review)

## 何时触发

当用户给出或 AI 提出涉及以下任一方面的方案时，自动启动审查：
- 新建 / 拆分模块或服务
- 数据结构或存储方案变更
- 对外接口 / 契约设计
- 前端架构或组件结构变更
- 部署 / 运行方案
- 安全相关（认证、权限、数据保护）
- 第三方能力选型
- 工具链 / 技术选型

不触发：小修、文案修改、单文件微调。

---

## 审查维度

### 1. 结构与边界
- 单元职责是否单一？
- 是否需要新建，还是可复用现有？
- 单元间是否通过明确契约通信？

### 2. 安全设计
- 是否需要权限模型？是否最小权限？
- 敏感数据是否加密 / 脱敏？
- 是否有操作记录？

### 3. 数据设计
- 是否满足规范化与访问模式？
- 高频访问路径是否有索引 / 优化？
- 是否需要软删除 / 状态标记？

### 4. 性能与扩展
- 是否需要缓存？
- 是否有耗时任务异步化？
- 是否支持水平扩展？

### 5. 可维护性
- 是否有健康检查 / 探活？
- 关键操作是否有日志？
- 配置是否可外部化？

详细标准见 `references/design-principles.md`；逐项检查见 `references/review-checklist.md`。

---

## 输出格式

审查完成后，按以下格式输出：

```markdown
## 方案审查

### 方案概述
> 一句话描述

### ⚠️ 风险项（必须解决）
- [ ] 风险1：描述 + 建议

### 💡 优化建议（建议采纳）
- [ ] 建议1：描述

### ✅ 合理项（无需改动）
- 项1：理由

### 综合评分
结构: ⭐⭐⭐⭐ / 安全: ⭐⭐⭐ / 数据: ⭐⭐⭐⭐ / 性能: ⭐⭐⭐

### 结论
✅ 通过（建议优化后执行）/ ⚠️ 有条件通过 / ❌ 需重新设计
```
