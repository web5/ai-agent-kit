# 设计原则（通用）

适用于任何系统、文档结构或流程的设计评审。

## 拆分与边界

- 按业务 / 职责域拆分，而非按技术层拆分。
- 每个单元有单一职责，边界清晰。
- 单元间通过明确契约通信，不共享内部状态。
- 避免过早拆分（一个功能一个单元）与过度耦合（共享内部）。

## 数据与设计

- 规范化为基础，再按访问模式优化。
- 设计结构时同步设计索引 / 检索路径。
- 用应用层保证一致性，避免隐式耦合。
- 大体量数据提前规划分区 / 分表策略。

## 对外契约

- 资源 / 接口命名用名词，语义稳定。
- 版本化对外能力，避免破坏性变更。
- 错误 / 响应格式统一。
- 操作具备幂等性。

## 结构原则

- 组件 / 模块驱动：整体 = 局部组合。
- 共享状态上提，集中管理。
- 按需加载，避免一次性全量。
- 样式 / 配置隔离，避免相互污染。
